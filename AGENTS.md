# Project Behavior Rules

For this project, use the simplest solid working path.

- Use proven working code paths to build new features whenever possible.
- Do not invent a new flow when Method A/B/G/SNAPWIN or another production path already works.
- Keep changes small, direct, and testable.
- Do not over-engineer. Use the right amount of thinking for the task.
- Start with the obvious blocker first.
- Prefer easy wins that make the system work reliably.
- Use ICF for debugging reports:
  - Issue
  - Cause
  - Fix
- When fixing migration code, preserve working Alma/Debian/Rocky/Windows behavior unless the task explicitly targets it.
- Show what task is being done, then do it.

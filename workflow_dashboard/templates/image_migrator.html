How this tool works

The Direct Shift and Lift tool is an automated "Snapshot & Re-deploy" pipeline driven entirely by the ospc2flex_image_migrator.py engine. It does not alter the live source VM. Instead, it creates an exact, point-in-time copy and processes that copy.

1. The OSPC Export Phase

Live Snapshot: The tool connects to the OSPC cloud via its OpenRC token and commands OpenStack to take an instantaneous Snapshot of the live Server Name you selected. Your original VM keeps running uninterrupted.

Local Download: It waits for the snapshot to transition to an ACTIVE state, then uses Glance to download the massive image file directly onto the local filesystem of your migration server (in a temporary working directory).

2. The Local Conversion Phase

Format Shifting (QEMU): Depending on your "Target Format" selection in the UI, the tool takes the downloaded image (usually vhd or raw) and runs it through qemu-img convert to transcode the entire filesystem package into a FLEX-native raw or qcow2 image.

3. The FLEX Import Phase

Glance Upload: The tool switches context, loading your FLEX OpenRC tokens. It uploads your newly converted image package directly into the FLEX OpenStack Image repository, tagging the visibility (e.g., Private or Shared).

Snapshot Cleanup: If you checked "Cleanup OSPC Snapshot", the tool logs back into the source OSPC cloud and deletes the temporary snapshot it created in Step 1 to save you storage costs.

4. The FLEX Deployment Phase

Auto-Provisioning: If "Test VM Options" are toggled ON, the tool skips the manual labor and immediately asks the FLEX compute scheduler (nova) to spawn a brand new VM using your uploaded image, applying the Target Flavor extracted from your CSV mapping, and attaching it to your target Network/Keypair.

5. The In-Flight Healing Phase

Because cloud IP addresses and volume UUIDs change between OSPC and FLEX, many VMs will crash during boot if they are severely hardcoded.

SSH Repair Injection: If "Guest Repair Options" are toggled ON, the tool uses your provided SSH Key to tunnel into the newly spawned Test VM in FLEX the second it boots up.

Automated Surgery: Once inside the guest OS, it:

  • Strips broken mounts from /etc/fstab so the VM doesn't hang looking for missing OSPC block volumes.
  • Restructures /etc/netplan or /etc/network/interfaces to force the VM to accept the new FLEX DHCP lease.
  • Wipes old cloud-init remnants and leftover qemu-guest-agent locks.
  • Automatically reloads explicitly listed Systemd services (like nginx or apache2) so your web applications come online.
Simply put: It clones it via a snapshot, shifts the format locally, uploads the clone to the new cloud, boots it up, and runs emergency surgery inside the OS to make sure it survives the transplant.

Global Migration Settings

SAVE VM Snapshot Location

This path saves the massive snapshot directly into the isolated Linux filesystem.

Local Disk on the Operator Laptop: You just type a folder path on your machine into the UI. The script will download the massive OSPC image locally, convert it utilizing your laptop's CPU, and upload it to FLEX.

Shared Drive Storage (NFS, SMB, Jumpserver share): Over in your Linux terminal, you mount your shared NAS drive or Jumpserver to a folder (e.g., sudo mount -t nfs 10.0.0.5:/shared /mnt/jumpserver). Then, you just type /mnt/jumpserver into the UI! The Python engine is completely tricked into downloading and converting the image straight across the network bridge onto the Jumpserver's storage disks.

Cloud Storage (S3, Swift, Rackspace Cloud Files): You use a tool like s3fs or rclone to mount your remote cloud bucket directly to your laptop. The migrator pipes the 100GB export file directly through the internet shell into the Cloud Storage bucket without filling up your laptop's hard drive!

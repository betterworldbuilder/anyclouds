  • File Manager (Upload/View): Visually tracks all generated shell scripts and allows you to manually inject external CSV lists (if bypassing Step 1).
  • Step 1 (Overview): {% if is_flex2flex %}Securely connects to FLEX/OpenStack APIs to discover source project servers, volumes, networks, security groups, and load balancers.{% elif is_hyperflex %}Creates the {{ provider_label }} source overview CSV using the same inventory schema consumed by the OSPC mapper and deployment generator.{% else %}Securely connects to Rackspace APIs to discover and download your legacy OSPC server inventory.{% endif %}
  • Step 1.5 (App Mapping): Actively scans instances to map live application and database dependencies via SSH.
  • Step 2 (Flavor Mapping): {% if is_flex2flex %}Creates FLEX-to-FLEX target mappings using the discovered source flavor and image names, producing the same flavor/block/LB map files as OSPC2FLEX.{% elif is_hyperflex %}Creates {{ provider_label }} to FLEX target mappings and emits the same flavor/block/LB map files as OSPC2FLEX.{% else %}Computes your legacy OSPC server sizes into modern OpenStack FLEX flavor equivalents.{% endif %}
  • Step 3 (Validation): Pre-flights your mappings against the live FLEX environment to ensure quotas and networks are valid before deploying.
  • Step 4 (Deploy Generation): Builds the infrastructure-as-code scripts (Networks, Keypairs, LBs, VMs) to spawn your FLEX clones.
  • Next Step: Paste the generated deploy script into the FLEX Deployment Dashboard (Stage 2).

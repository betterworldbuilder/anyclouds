🔴 Method 3 — OSPC K8 → Flex Magnum 2025.2 Update Export workloads from OSPC cluster · Design & validate ClusterTemplate · Provision via Magnum 2025.2 · Restore on Flex
⚠ Architecture rule: Magnum 2025.2 creates a new cluster from a ClusterTemplate — do not attempt to import the old OSPC control plane. This pipeline exports source cluster config, Helm metadata, image references and PVC metadata; then designs and validates a Magnum 2025.2 ClusterTemplate (COE, image os_distro, network/volume driver, LB, NodeGroup); then provisions a fresh Flex Magnum cluster, transforms manifests for Flex compatibility, and restores workloads in dependency order.

📥 Stage 1 runs in remote master mode: SSH to the OSPC master → run all kubectl/helm exports there → copy results back locally via scp → clean up remote temp dir. Inputs required: OSPC Master IP · SSH User · SSH Key Path. Set them in the config panel below.

🔷 Stage 2 — Design Template: Before creating the cluster, validate ClusterTemplate parameters against Magnum 2025.2 constraints: COE=kubernetes, image os_distro=fedora-coreos, network_driver=flannel|calico, volume_driver=cinder. Heat driver is deprecated — do not set it.

📋 9-Stage Pipeline Summary ▼
Stage 1 — Export from OSPC: SSH to the OSPC Kubernetes master node, run kubectl and helm export commands remotely, then scp the resulting bundle back to the local workstation. The OSPC cluster is read-only during this step — no changes are made.

Stage 2 — Design & Validate ClusterTemplate: Before provisioning anything on Flex, define and validate the Magnum 2025.2 ClusterTemplate parameters: COE (kubernetes), image with os_distro=fedora-coreos, network driver (flannel or calico), volume driver (cinder), LoadBalancer driver, and NodeGroup shapes. This stage produces a cluster-template.yaml design artifact reviewed before any API calls are made.

Stage 3 — Create Flex Magnum Cluster: Submit the validated ClusterTemplate to the Flex Magnum API and create the Cluster object. Poll until CREATE_COMPLETE, then download and verify the Flex kubeconfig. The Heat driver is explicitly not used — Magnum 2025.2 manages the cluster lifecycle directly.

Stage 4 — Transform Manifests for Flex: Process the exported OSPC manifests through the transform pipeline: patch StorageClass to use the Cinder CSI driver, update Ingress class annotations, remove OSPC-specific node selectors and taints, and verify CNI and storage driver compatibility with Flex.

Stage 5 — Restore Workloads to Flex: Apply CRDs first (required before any custom resources), then restore namespaces, RBAC, ConfigMaps/Secrets, Services, Deployments/StatefulSets/DaemonSets, and HPA in dependency order. Helm-managed workloads are re-installed via helm upgrade --install rather than raw manifest apply.

Stage 6 — Restore Data: Handled separately from workload restore. Restore Cinder PVC data (snapshots or rsync), re-attach volumes to the correct pods, and verify database contents. The Cinder volume driver replaces any Ceph-direct or NFS mounts from OSPC.

Stage 7 — Test & Validate: Run Magnum cluster health checks (openstack coe cluster show), deploy a LoadBalancer test Service to confirm Octavia LB provisioning end-to-end, execute application smoke tests and readiness probes, and confirm all PVCs are Bound.

Stage 8 — Cut Over: Only after all Stage 7 checks pass: update DNS records or load balancer VIPs to point to the Flex cluster, quiesce writes on the OSPC side, perform a final data sync if needed, and confirm traffic flowing on Flex.

Stage 9 — Rollback (if needed): If any critical failure occurs after cutover, revert DNS/LB to OSPC, restore any delta data written to Flex back to OSPC, and document the failure root cause. The rollback window remains open until OSPC is formally decommissioned.

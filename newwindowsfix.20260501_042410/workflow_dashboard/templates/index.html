OSPC Scanner and Deployment Script Generator

Connects to your OSPC Rackspace account, scans your existing server inventory, maps legacy OSPC flavors to equivalent FLEX flavors, validates your target environment, then auto-generates ready-to-run deployment shell scripts to clone your entire OSPC infrastructure into the Flex OpenStack cloud.

  • File Manager (Upload/View): Visually tracks all generated shell scripts and allows you to manually inject external CSV lists (if bypassing Step 1).
  • Step 1 (Overview): Securely connects to Rackspace APIs to discover and download your legacy OSPC server inventory.
  • Step 1.5 (App Mapping): Actively scans instances to map live application and database dependencies via SSH.
  • Step 2 (Flavor Mapping): Computes your legacy OSPC server sizes into modern OpenStack FLEX flavor equivalents.
  • Step 3 (Validation): Pre-flights your mappings against the live FLEX environment to ensure quotas and networks are valid before deploying.
  • Step 4 (Deploy Generation): Builds the infrastructure-as-code scripts (Networks, Keypairs, LBs, VMs) to spawn your FLEX clones.
  • Next Step: Paste the generated deploy script into the FLEX Deployment Dashboard (Stage 2).

File Manager & Uploads

For most typical migrations, you will execute Step 1 to automatically generate your Server Inventory lists by pointing it directly at your Rackspace Account API.
However, sometimes you will be given a massive spreadsheet list of servers manually by a client, or you will already have a servers_to_migrate.csv file created from a different tool.
You can upload those files here so they appear in dropdowns across the dashboard! (Uploaded files are stored in the uploads/ directory)

    1) OSPC Account Inventory Idle

    Authenticate with your Rackspace OSPC Credentials and click the Run Account Scanning button below.

    🛡️ Security Group Rules 0

    Detailed firewall rules discovered from OSPC Neutron Security Groups. Each card shows ingress/egress rules with protocol, port range and CIDR. Use the per-SG or bulk import button to push groups directly into FLEX via the OpenStack CLI.

    1.5) Application Dependency Mapping Idle

    Map application relationships using deep Active Scanning or intelligent Metadata Inference.

    2) Flavor + Block + LB Mapping Idle

    Select your deployment region, then select your Account Overview file, choose any optional DB/Floating IP behaviors, and press Run Flavor Mapper.

    Regional target flavor catalogs are loaded from uploads/flavors/.

    Creates similar spec Compute Instances as targeted replacements for Cloud Database Instances.

    Floating IPs will be assigned for every VM by default.

    3) Pre-Deploy Validation Idle

    Load your Flavor Mapping, Block Mapping, and optional LB Mapping files then click the Validate Inputs button.

    Validation Findings

    4) Generate Deploy Artifacts Idle

    If duplicate server names exist, generation auto-suffixes names (for example linux-server-1-2). This step can still run even if validation failed.

    Generated deploy scripts continue on per-step errors by default and write a results CSV. Enable fail-fast to stop on first failed step.

    Linux instances use Key Name and that keypair must already exist in the target project. Windows instances can auto-generate random admin passwords (12-16 chars, alphanumeric) and export them to a credentials CSV.
